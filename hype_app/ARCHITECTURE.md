# ARCHITECTURE - FinPulse Hype

## 💫 Поток данных

```text
seed_articles.json ──┐
                     ├─> ingest (Polars, strict schema)
RSS 2.0 XML ─────────┘        │
                              v
                    models (Pydantic v2, strict)
                              │
                              v
                 storage (DuckDB: INSERT OR REPLACE)
                              │
        ┌─────────────────────┼──────────────────────┐
        v                     v                      v
   analytics (Polars)     API (FastAPI)          CLI (Typer+Rich)
   top/day/keywords       + summarize            stats/export
                              │
                              v
                     ai.port -> ExtractiveFallback / LangChainAdapter

dashboard (Streamlit) читает те же слои: хранилище + аналитика + порт AI
```

## 🧱 Слои

| Слой | Модуль | Ответственность |
|---|---|---|
| Приём | `ingest.py` | seed-JSON через Polars со строгой схемой; RSS 2.0 средствами stdlib |
| Домен | `models.py` | Pydantic v2, `extra=forbid`, границы на пагинацию |
| Хранение | `storage.py` | DuckDB-репозиторий, параметризованный SQL, наивные UTC-таймстампы |
| Аналитика | `analytics.py` | чистые Polars-агрегации без IO |
| AI | `ai/` | порт (Protocol) + extractive-fallback + LangChain-адаптер (lazy) |
| API | `api/` | фабрика, маршруты, middleware (request-id, error-envelope, CORS) |
| CLI | `cli.py` | Typer-команды, Rich-таблицы и прогресс |
| Dashboard | `dashboard.py` | Streamlit: фильтры, графики, панель суммаризации |

## 📜 ADR

### ADR-1: AI за портом с адаптерами
**Контекст:** LLM-стек нестабилен (версионный дрейф LangChain), ключи есть не всегда.
**Решение:** `SummarizerPort` (Protocol) + два адаптера: детерминированный `ExtractiveSummarizer` (по умолчанию) и `LangChainSummarizer` (opt-in). Фабрика `build_summarizer` в `api/app.py`.
**Последствия:** MVP полноценно работает и тестируется без сети и секретов; смена LLM-провайдера - это один адаптер, а не переписывание API.

### ADR-2: Polars вместо pandas
**Контекст:** нужны быстрые агрегации и жёсткие схемы.
**Решение:** все трансформации на Polars; схемы заданы явно (`ARTICLE_SCHEMA`, `_BASE_SCHEMA`), `strict=True`.
**Последствия:** битые входные данные падают рано и громко; lazy-режим доступен на вырост.

### ADR-3: DuckDB как serverless-хранилище
**Контекст:** демо-объёмы, аналитические запросы, ноль ин фраструктуры.
**Решение:** файл-БД (`data/hype.duckdb`, в .gitignore), `INSERT OR REPLACE`, параметризованный SQL.
**Последствия:** ноль операционки; при росте объёмов репозиторий подменяется, API-слой не меняется.

### ADR-4: LangChain - опциональная экстра-группа
**Контекст:** ключ у большинства разработчиков отсутствует; тяжёлые зависимости замедляют uv sync.
**Решение:** зависимость в `[project.optional-dependencies] ai`; адаптер импортирует langchain внутри функции.
**Последствия:** базовая установка не тянет LLM-стек; без провайдера - ясная ошибка вместо молчаливой деградации.

### ADR-5: строгая изоляция hype_app
**Контекст:** в репозитории живут существующие эксперименты (`HelloPython/` и корневой `.gitignore`).
**Решение:** всё новое - внутри `hype_app/`; отдельный workflow `hype.yml` с фильтром по путям `hype_app/**`; существующие файлы не изменяются.
**Последствия:** независимый CI-прогон и жизненный цикл; ничего из существующего не сломано.

## 🙈 Ограничения слепой записи и как они закрыты

- станция-исполнитель не запускает Python-код (в её песочнице нет pip/pytest), поэтому: строгие type hints, явные схемы Polars/Pydantic, lazy-импорт тяжёлых зависимостей;
- исполнение делегировано: тесты и ruff/pytest гоняются в GitHub Actions (`hype-ci`) и QA-прогоном Qwen;
- `uv.lock` генерируется при первом реальном прогоне (uv sync), а не пишется вслепую;
- секреты: только `.env.example` с плейсхолдерами; ключ провайдера живёт в его стандартной переменной окружения, в коде и diff её имена отсутствуют.

## 🔮 На вырост

- фоновые RSS-обновления по расписанию за тем же портом приёма;
- кеш суммаризаций (dedup по хешу текста);
- подмена репозитория на табличный сервис при росте датасета (остальные слои не меняются).
